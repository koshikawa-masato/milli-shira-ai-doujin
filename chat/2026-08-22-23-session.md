## 失敗と学び

- LoRA の倍率を下げても顔は寄らない。素体の長文説明を付けると逆に `krpn` より強く効いて別人になる → `krpn` に顔を任せ、衣装だけ言葉で指定する
- 同 seed で構図を揃えると表情が弱くなる。正方形 1024 の全身では顔の画素が足りず、目を大きく描けない → 縦長にすると改善
- 実行中のスクリプトを上書きしてジョブを壊した
- 参照画像 4 枚の編集で VRAM が溢れ、1 step 150 秒
- ローカル VLM（gemma4 / Qwen3-VL 32B）は位置関係の判定に使えなかった（前日）

## 追記（08-23 深夜〜午前）: RunPod を「使うときだけ動く」形に

- 天の声「結構時間かかりますね」→ 原因は 1 枚ごとのモデル読込（5〜6 分）と、待機ループの pgrep 自己一致。`edit_batch.sh` で 1 プロセス連続処理に（4 枚 574 秒）
- 「終わった瞬間に止めて、やる時に再スタートさせる処理」→ Serverless と Pod 自動起動停止の 2 案 → **学習フェーズなので Pod 案**。Pi5 の中継ワーカー（Pod モード）、ギャラリーの「編集」タブ、Mac メニューバー **RunPodBar**（稼働状態・残高 $・消費/h・ジョブ）
- 「残り金額も出ませんか」→ GraphQL `myself{clientBalance currentSpendPerHr}` で残高表示
- 「金額が減るタイミング」→ 秒課金、入り切りの手数料なし、停止中は Network volume $0.015/h のみ。起動 1 回の空回り ≒ $0.1〜0.2
- 三面図 v2: 天の声「Claude Code が画像を見て問題ないと思いますか？」→ 正直に NG 箇所を列挙（襟の線、裾、横の襟なし、後ろの線 1 本・スカートの×）。「前と同じで修正、でいけませんか」→ 編集で当てる方針に。結果は「直した箇所は直るが別の箇所が崩れる」。次の案: 襟だけ上半身を 2 倍に切り出して編集し貼り戻す
- つまずき: Pod の env 更新でコンテナ再作成（実行中バッチ消失）、ghcr ビルドの pip 衝突（venv で回避）、api.runpod.io が Python-urllib の UA を 403 で弾く（UA 指定で回避）
