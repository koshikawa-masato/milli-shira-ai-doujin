## 教訓
- **実行中の bash スクリプトを上書きしない**（読み込み途中から壊れる）。差し替えはキューが空いてから
- 参照画像を増やすほど編集の VRAM が跳ね上がる。16GB では 1 枚参照の 1024² が実用上限
- 大きい GPU でも **1 枚ごとにプロセスを起動すると読込が支配的**になる。複数枚は `--from_file` で 1 プロセスにまとめる
- **Pod の env を更新（update-pod）するとコンテナが作り直される**。実行中のジョブは消え、/root（シンボリックリンク・apt で入れた tmux・authorized_keys）は初期化され、ssh の公開ポートも変わる。/workspace（Network volume）だけが残る。→ env 変更は Pod が空いているときに。復元は `pod_boot.sh`。ssh 先のポートは毎回 API から取る
- 天の声の指示を Claude が言い換えると内容が歪む。実文を見せる。Oracle の役割（顔＝A、等身＝B）を勝手に再解釈しない
- AI の編集は「小さな変更」（口を閉じる）ほど効かず、元に戻すか写実化する。線 1 本の変更は画像処理で描くほうが確実
- `pgrep -f <語>` を ssh 越しに使うと自分のコマンド行にマッチする。プロセス待ちは tmux セッションの有無か pid ファイルで
- LoRA を弱めても顔は「似て非なる」になる。完全一致が要るなら編集で画素を保つ
